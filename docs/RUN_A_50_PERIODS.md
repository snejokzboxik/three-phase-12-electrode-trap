Подготовлено 28.10.2026. Обновление: пользователь завершил полный расчёт
на 50 Ts; [анализ готовых данных](LONG_A_50_RESULTS.md) сохранён отдельно.
Повторный запуск основной команды проверит готовый результат, а не начнёт
тот же расчёт заново.

При первоначальной подготовке полного расчёта ещё не было;
Готовность входов проверена; выполнен отдельный короткий расчёт на настоящем
FEM P4 с двумя сохраняемыми блоками и сравнением с непрерывным запуском.
Все 97 тестов проекта пройдены, включая 8 тестов длительного запуска.
Прежние 151 артефакт проверки A/B/C и 53 замороженных входа сохранили SHA.

При последующем анализе добавлены 3 диагностических теста; текущий полный
набор — 100 пройденных тестов. Инструкции запуска ниже сохранены.

## Запуск

Открой PowerShell и выполни:

```powershell
Set-Location -LiteralPath 'D:\VS projects\LaTeX\Снежек статья\three-phase-12-electrode-trap'
powershell -ExecutionPolicy Bypass -File .\scripts\run_A_50_periods.ps1
```

Команда запускает **одну точную траекторию A** с t=0, на P4-сетке 35 мкм,
с RF-фазой 0 и DOP853 T_RF/100. Уже готовое FEM-поле загружается из кэша;
заново строить сетку и решать задачу Лапласа не нужно. Траектория из
прежнего расчёта на 10,25 Ts в первый запуск не подставляется.

Ожидаемая длительность — около 75–90 минут по скорости прошлых запусков;
это оценка, зависящая от загрузки компьютера. Оставь окно PowerShell открытым.
В начале проверяются файлы и загружается поле; эта стадия занимает некоторое
время до появления первого сообщения об интегрировании.

Проверить только готовность, без расчёта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_A_50_periods.ps1 -CheckOnly
```

Успешный ответ — `[READY]`. Эта команда не запускает траекторию.

## Параметры

- A — полный закон `m r̈=q E_FEM(r,t)`, прямой несглаженный градиент P4.
- q=+1e−12 Кл, m=1e−15 кг, U0=250 В, f=100 кГц; без DC, трения и гравитации.
- Начальное полное RF-состояние то же, что в завершённой проверке:
  `[0.0010000000000544395, -3.346946549194907e-7,
  0.21036209953962762, 1.8359318543806833e-8]` в единицах `[м, м, м/с, м/с]`.
  Ненулевая полная скорость учитывает микродвижение; медленный старт задан
  как R0=(1 мм,0), V0=0 в исходном протоколе.
- Опорный медленный период Ts=0,023093891788417812 с фиксирован по прежнему
  протоколу. Продолжительность — 50 таких периодов, округлённых вверх до
  целого RF-периода: **115470 RF-периодов, 1,1547 с ≈50,00023429 Ts**.
  После расчёта измеренный период может немного отличаться от опорного.
- Вывод — 64 интервала на RF-период: 7 390 081 полное состояние.
- Контрольный блок — 2000 RF-периодов (0,02 с), всего 58 блоков.
- Файлы и исходники фиксируются по SHA; при несовпадении входов продолжение
  отклоняется, а прежние данные не перезаписываются другой физической моделью.

## Как видеть прогресс

Сообщения появляются при завершении блока и примерно каждые 30 секунд
интегрирования. Например:

```text
[RUNNING] 24.25% | 12.125 slow periods | checkpoints 13/58 | ETA 57.2 min
[CHECKPOINT_SAVED] ...
```

`slow periods` — достигнутое время, делённое на опорный Ts; `checkpoints` —
число целиком сохранённых блоков; `ETA` — текущая приблизительная оценка
оставшегося времени. В начале она может быть неточной.

В другом окне PowerShell, из той же папки проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_A_50_periods.ps1 -Status
```

Команда покажет последний прогресс, время последнего обновления в UTC
и точку сохранения. Если процесс остановился, будет показан `INTERRUPTED`
либо сохранённая ошибка, а не ложное сообщение о продолжающемся расчёте.

## Как понять, что расчёт завершён

В конце должны появиться сообщения:

```text
[POSTPROCESSING] 100.00% ...
[VERIFYING] 100.00% ...
[COMPLETED] 100.00% ... COMPLETED.json written; result files verified.
```

**Признак завершения — `[COMPLETED]` и файл `COMPLETED.json`.**
При 100% интегрирование уже закончено, но сборка и проверка файлов ещё
могут продолжаться. По одному проценту завершённость не определять.

Результат находится в папке:

```text
outputs/abc_validation/long_A/v1/A_P4_h35_phase0_fine_50Ts_from_zero/
```

Основные файлы:

| Файл | Содержимое |
|---|---|
| `trajectory.npz` | Полная траектория: `time_s`, `states`=(x,y,vx,vy) в СИ, `triangles` |
| `slow_samples.npz` | Центрированное среднее координат за RF-период, затем один отсчёт на RF-период |
| `trajectory_overview.png` | Медленные x(t), y(t), XY-траектория и расстояние от центра |
| `summary.json` | Длительность, радиусы, измеренный период при наличии достаточных колебаний |
| `COMPLETED.json` | Маркер завершения и SHA итоговых файлов |
| `settings.json` | Параметры, начальное состояние, версии и SHA входов/ядра |
| `status.json`, `run.log` | Текущий статус и журнал |
| `checkpoints/` | Блоки траектории, непрерывная цепочка состояний, аудит пересечений |
| `source_snapshot/`, `source_manifest.json` | Исходники фактически использованного расчёта |

Ориентировочный объём всех данных с checkpoint — порядка 0,5–1 ГБ.

Полная проверка результата после завершения:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_A_50_periods.ps1 -Verify
```

Успешный ответ — `[VERIFIED]`: проверяются контрольные суммы,
все 58 блоков, непрерывность состояний, начальный и конечный моменты
и число отсчётов. Это чтение результата без повторного расчёта траектории.

## Остановка, продолжение и ошибки

Для остановки нажми Ctrl+C. Повторный запуск **той же основной команды**
продолжит эту 50-периодную траекторию с последнего целого checkpoint.
Завершённые блоки повторно не считаются; незаписанная часть текущего блока
может быть потеряна, обычно это около 1–2 минут работы.

Первое выполнение создаёт именно траекторию с t=0. Возобновление после
остановки использует только её собственные блоки, не прежние пилоты.
После успешного завершения та же команда проверит готовый результат
и не начнёт второй часовой расчёт. Два процесса не могут одновременно
писать в одну папку.

При `[FAILED]` или `[ERROR]` смотри `error.txt` (если создан), `run.log`
и сообщение в окне. Ошибка не получает маркер успешного завершения.
Не обходить SHA-проверки и не удалять checkpoint для маскировки ошибки.

## Учёт RF-времени и проверка запуска

Блоки заканчиваются на целых RF-периодах. Для начала блока t_k=N_k/f:

```text
sin(Omega*(t_k+tau)+phi0) = sin(2*pi*N_k + Omega*tau+phi0)
                         = sin(Omega*tau+phi0).
```

Внутри блока интегратор использует локальное время tau и неизменную phi0;
физическая RF-фаза согласована точно по целому числу циклов. Координаты
и скорости при переходе сохраняются без сдвигов, а абсолютные времена вывода
восстанавливаются по целым индексам RF-отсчётов. Это позволяет избежать
потери точности при вычитании близких больших времён на длинном расчёте.
Прежнее проверенное численное ядро и результаты A/B/C не изменялись.

При необходимости повторить короткую техническую проверку:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_A_50_periods.ps1 -SmokeTest
powershell -ExecutionPolicy Bypass -File .\scripts\run_A_50_periods.ps1 -SmokeTest -Verify
```

Она использует отдельную папку `...smoke_RF64_<source_hash>/`, считает
два блока по 32 RF-периода и сравнивает их с непрерывным расчётом на
64 RF-периода. Её `COMPLETED.json` относится только к тесту, не к 50 Ts.

При дальнейшем исследовании контрольные варианты можно запустить отдельно
через `-Mesh 50` и/или `-Level coarse`: они имеют свои папки результатов.
По умолчанию эти дополнительные расчёты не запускаются.

**Завершение одной траектории A не подтверждает её численную сходимость
на 50 Ts и не является готовым сравнением с B/C.** Такие проверки выполняются
отдельно после получения данных; в итоговом JSON это явно отмечено как
`convergence_status: not_assessed_for_this_duration`.
